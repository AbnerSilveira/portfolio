## Projeto #13 — IDS

**Matéria:** Redes de Computadores II
**Impacto:** 🔴 Alto
**Categoria:** Sandbox
**Esforço:** 3 semanas

### Objetivo

Intrusion Detection System com:

- **Engine de regras Snort-like** — regras declarativas em sintaxe customizada
- **Análise em PCAPs** (offline) e **stream live** (via tap em interface)
- **Detecção de anomalias baseada em baseline** — o IDS aprende padrões "normais" e alerta em desvios
- **Correlação de alertas** — múltiplos alertas do mesmo ator viram "campanha"

### Evolução natural do Sniffer (#2)

O sniffer captura e detecta 4 patterns hardcoded. O IDS generaliza: regras carregadas de arquivo, engine extensível, correlação temporal.

**Não descartar o sniffer.** Reutilizar a camada de captura do sniffer via import (ambos são `@projects/*` e podem se referenciar via `workspace:*` se extrair a parte de captura para package separado).

### Stack

| Camada           | Tecnologia                          |
| ---------------- | ----------------------------------- |
| Captura          | Python + Scapy (herdado do sniffer) |
| Engine de regras | Python                              |
| Banco            | PostgreSQL (reusa do honeypot)      |
| Stream           | Redis pub/sub                       |
| Dashboard        | Next.js + websocket                 |

### Sintaxe de regras customizada

Inspirada em Snort, mas simplificada:

```
rule "http_suspicious_user_agent" {
  protocol tcp
  port 80, 443
  payload contains "sqlmap"
  severity high
  message "SQLMap scanner detected"
}

rule "dns_beaconing" {
  protocol udp
  port 53
  statistics {
    same_source: true
    interval_variance: < 0.1
    count: > 20
    window: 300s
  }
  severity medium
  message "DNS beaconing pattern"
}
```

### Passo a passo

**Semana 1 — Motor básico**

Dia 1: Setup + parser da sintaxe de regras (regex para linguagens simples; considerar lark-parser se ficar complexo)
Dia 2-3: Rule compiler — transforma regra em função Python
Dia 4: Matcher aplicando regras em PCAPs
Dia 5: 20 regras iniciais (SQLi, XSS em tráfego HTTP; DNS tunneling; port scan)
Dia 6-7: Testes TDD com PCAPs fixture

**Semana 2 — Correlação e anomaly detection**

Dia 1-2: Correlator — janela deslizante, agrupamento por IP source
Dia 3: Baseline learner — aprende padrões "normais" em dataset calibração
Dia 4: Anomaly detection — flags desvios do baseline
Dia 5-6: Storage no Postgres + pub/sub no Redis
Dia 7: Testes de integração

**Semana 3 — Dashboard + sandbox**

Dia 1-2: Dashboard Next.js com 4 views: alertas live, campanhas correlacionadas, regras ativas, estatísticas
Dia 3: Recharts para timeline e heatmaps
Dia 4: Demo sandbox — usuário escolhe "campanha" pré-gravada (PCAP), vê IDS detectando em tempo real
Dia 5: Integração com `threat-intel-aggregator` — enrich alerts com reputação
Dia 6: MDX
Dia 7: Deploy

### Conceitos a destacar no MDX

- **False positive rate** — IDS sofre com ruído. Explicar trade-off sensitivity/specificity
- **Evasion techniques** — fragmentação, encoding, timing — e como o IDS mitiga
- **Differences from firewall/WAF** — detection-only vs prevention

## Projeto #14 — Threat Intel Dashboard ⭐

**Matéria:** Analytics - Inteligência de Negócios
**Impacto:** 🔴 Alto
**Categoria:** Live
**Esforço:** 3 semanas

**Projeto-hero visual.** O mais atraente esteticamente do portfólio. Vale investir em design.

### Objetivo

Dashboard que agrega, correlaciona e visualiza threat intelligence de múltiplas fontes:

- **AbuseIPDB** — reputação de IPs
- **VirusTotal** — hashes de malware, domínios maliciosos
- **Shodan** — dispositivos expostos, CVEs em produtos
- **URLhaus** (abuse.ch) — URLs de distribuição de malware
- **ThreatFox** — IOCs recentes
- **AlienVault OTX** — pulses comunitários
- **CISA KEV** — CVEs exploradas ativamente

### Visualizações obrigatórias

- **Heatmap global** — ameaças por país (Leaflet + choropleth)
- **Timeline de CVEs críticas** — top 10 mais exploradas nos últimos 30 dias
- **Sankey diagram** — fluxo ameaças → setores afetados
- **Rede de correlação** — IPs malware conectados a domínios a famílias
- **Feed live** — alerts chegando em tempo real

### Stack

| Camada     | Tecnologia                                                      |
| ---------- | --------------------------------------------------------------- |
| Aggregator | `services/threat-intel-aggregator` (já existe desde o honeypot) |
| Pipeline   | NestJS + Bull (queue de jobs de fetch)                          |
| Banco      | PostgreSQL + Redis                                              |
| Dashboard  | Next.js + Recharts + D3.js + Leaflet                            |
| Animações  | Framer Motion                                                   |

### Passo a passo

Dia 1: GlobalHeatmap com Leaflet (dados de país por IP ameaças)

Dia 4: CorrelationGraph (force-directed com D3)
Dia 5: LiveFeed com WebSocket + animações de entrada
Dia 6: Polimento visual — typography, spacing, dark mode
Dia 7: MDX + deploy

### Custos operacionais

Em produção, queries para providers pagam rate limit. Estratégia:

- Cache de 24h para IPs/hashes consultados
- Free tiers são generosos o suficiente para portfólio
- Se algum provider exigir subscription, documentar no MDX e mostrar fallback

### Design

Este projeto merece investimento visual extra:

- Paleta escura com accents coloridos por severidade (CVSS score → cor)
- Transições suaves entre views
- Cada widget é um card clicável que expande
- Lovable é excelente aqui — gerar o layout lá, refinar no Cursor
