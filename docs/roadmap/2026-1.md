## Projeto #15 — IoT Security Framework

**Matéria:** Sistemas Distribuídos e IoT
**Impacto:** 🔴 Alto
**Categoria:** Vídeo
**Esforço:** 4 semanas

### Objetivo

Framework de segurança para dispositivos IoT que demonstra 4 capacidades:

1. **Detecção de firmware adulterado** — agente no dispositivo periodicamente hashea áreas de firmware, reporta ao servidor, compara com baseline
2. **Comunicação MQTT com TLS mútuo** — broker e devices se autenticam por certificados
3. **Detecção de dispositivos rogue** — servidor monitora rede e detecta MACs/fingerprints não cadastrados
4. **Atualização OTA assinada** — servidor envia firmware, device valida assinatura antes de instalar

### Hardware

**3 ESP32** (opcionalmente 5):

- Device A — "normal"
- Device B — "normal" (para demonstrar população de devices)
- Device C — adulterado (firmware modificado para simular comprometimento)

Custo: ~R$ 50 por ESP32. Investimento razoável para o projeto-hero de 2026/1.

Alternativa sem hardware: simular ESP32s em container Docker (QEMU ou simulador da Espressif). Perde parte do impacto visual do vídeo, mas é viável se orçamento apertar.

### Stack

| Camada                  | Tecnologia                            |
| ----------------------- | ------------------------------------- |
| Agent (firmware device) | C/C++ com ESP-IDF                     |
| Servidor central        | Go (bom para concorrência MQTT + TLS) |
| Broker MQTT             | Mosquitto com mTLS                    |
| Dashboard               | Next.js                               |
| Banco                   | PostgreSQL                            |

### Por que Go no servidor

Adiciona mais uma linguagem ao portfólio (total: 7 — Python, TS, JS, Rust, SQL, Dart, Go). Go é comum em segurança de rede e infraestrutura (Docker, Kubernetes, Traefik são Go).

### Passo a passo

**Semana 1 — Firmware + MQTT**

Dia 1-2: Setup ESP-IDF, primeiro firmware "hello world" conectando Wi-Fi
Dia 3: Mosquitto com TLS mútuo — gerar CA, cert do broker, certs de cada device
Dia 4: Firmware publica heartbeat via MQTT
Dia 5-6: Servidor Go consumindo MQTT, gravando devices no Postgres
Dia 7: Dashboard Next.js exibindo lista de devices online

**Semana 2 — Attestation**

Dia 1: Firmware calcula SHA-256 de partições de memória
Dia 2: Publica hashes periodicamente via MQTT
Dia 3: Servidor mantém baseline de hashes conhecidos
Dia 4-5: Comparação e alertas quando hash diverge
Dia 6: Versão "tampered" do firmware (modificar string no binário)
Dia 7: Demonstrar detecção em vídeo

**Semana 3 — Rogue detection + OTA**

Dia 1: Scanner de rede no servidor (nmap programático ou ARP sweep)
Dia 2: Whitelist de MACs cadastrados
Dia 3: Alertas para MAC desconhecido na rede
Dia 4-5: OTA signing — servidor assina binário com chave privada, device valida com pública embarcada
Dia 6: Flow completo de update
Dia 7: Rollback em caso de falha

**Semana 4 — Dashboard + vídeo**

Dia 1-2: Dashboard completo — devices, alerts, OTA status
Dia 3: Visualização de topologia de rede
Dia 4: Gravar vídeo demo com 3 ESP32s reais
Dia 5: Edição do vídeo com narração
Dia 6: MDX com detalhes técnicos
Dia 7: Deploy + upload YouTube

### Protocolo custom — documentar

Criar `docs/protocol.md` dentro do projeto documentando o protocolo MQTT usado:

```
Topic structure:
  iot/<device_id>/heartbeat
  iot/<device_id>/attestation
  iot/<device_id>/ota/request
  iot/<device_id>/ota/status
  iot/server/broadcast/<category>

Payload format: CBOR (menor que JSON para devices constrained)

Message types:
  HEARTBEAT: { ts, uptime, fw_version, rssi }
  ATTESTATION: { ts, partition, hash, signature }
  OTA_REQUEST: { current_version }
  OTA_OFFER: { new_version, url, signature }
```

### Critérios de aceite

- [ ] 3 ESP32s conectados simultaneamente, autenticados por mTLS
- [ ] Device C (tampered) detectado via attestation em menos de 60 segundos após boot
- [ ] Rogue MAC aparece no dashboard em 30 segundos após entrar na rede
- [ ] OTA completa com sucesso em device normal
- [ ] OTA com assinatura inválida é rejeitada
- [ ] Vídeo demo tem no máximo 5 minutos e mostra os 4 cenários
